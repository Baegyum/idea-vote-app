# 새 작업 시작하기

새 작업을 시작할 때 브랜치를 만드는 절차다. 초보자가 혼자 하면 빠뜨리기 쉬운
단계(최신 상태로 맞추기, 이름 규칙, 저장 안 된 변경 확인)를 대신 챙긴다.

## 절차

### 1. 지금 상태 확인

```
git status --porcelain
git branch --show-current
```

- **저장 안 된 변경이 있으면 먼저 멈춘다.** 그 변경이 무엇인지 사용자에게 보여주고,
  지금 브랜치에서 커밋할지 / 새 브랜치로 가져갈지 물어본다. 임의로 버리지 않는다.
- 이미 `main` 이 아닌 브랜치 위에 있으면, 그 작업이 끝난 것인지 확인한다.
  안 끝났으면 새 브랜치를 만들지 말고 하던 걸 계속하라고 안내한다.

### 2. main 을 최신으로

```
git checkout main
git pull --ff-only origin main
```

이걸 빠뜨리면 남이 이미 고친 걸 모르고 작업해서 나중에 충돌이 난다.
`--ff-only` 는 "깔끔하게 이어붙일 수 있을 때만 받아라"는 뜻이라, 꼬인 상태를 조용히 만들지 않는다.

### 3. 브랜치 이름 정하기

무엇을 만들지 사용자에게 물어보고, 아래 표에서 종류를 고른다.

| 종류 | 언제 |
|---|---|
| `feat/` | 새 기능 |
| `fix/` | 버그 수정 |
| `docs/` | 문서만 |
| `chore/` | 설정, 정리 |

**이름은 영어 소문자와 하이픈만 쓴다.** 한글이나 띄어쓰기가 들어가면 다른 컴퓨터에서 깨진다.
사용자가 한글로 말하면 영어로 바꿔서 제안하고, 그 이름으로 괜찮은지 확인받는다.

예: "댓글 폼 만들래" → `feat/comment-form`

### 4. 브랜치 만들기

```
git checkout -b <정한-이름>
```

### 5. 사용자에게 알려주기

만든 뒤에는 이렇게 알려준다. 초보자에게는 "지금 어디에 있는지"가 가장 헷갈리는 부분이다.

- 지금 어느 브랜치 위에 있는지
- 여기서 뭘 고쳐도 `main`(배포되는 진짜 코드)은 안전하다는 것
- 작업이 끝나면 무엇을 하면 되는지 (커밋 → 푸시 → PR)

## 주의

- **`main` 위에서는 커밋도 푸시도 하네스가 막는다.** 이건 정상이다.
  차단 메시지가 뜨면 브랜치를 안 만든 것이니, 이 절차를 처음부터 밟으면 된다.
- 브랜치를 만들기만 하고 커밋까지 대신 해주지 않는다. 무엇을 고칠지는 사용자가 정한다.
