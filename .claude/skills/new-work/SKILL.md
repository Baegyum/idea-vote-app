# 새 작업 시작하기 — 내 복사본 만들기

`main` 에서 바로 작업하면 팀 전체가 위험해진다. 그래서 작업 하나마다
"내 복사본"을 만들고 그 안에서만 고친다. 이 스킬은 그 절차를 대신 챙긴다.

초보자가 혼자 하면 빠뜨리기 쉬운 것 세 가지를 특히 챙긴다:
최신 상태로 맞추기, 이름 규칙, 저장 안 된 변경 확인.

## 말투 규칙

재환·위진은 개발이 처음이다. 설명할 때 팀 문서(`docs/01-git-기초.md`)의 말을 그대로 쓴다.

| 이 말을 쓴다 | 이 말은 피한다 |
|---|---|
| 내 복사본 | 브랜치 (처음 나올 때만 괄호로 병기) |
| 저장 지점 만들기 | 커밋 |
| GitHub에 올리기 | 푸시 |
| 합쳐달라고 요청하기 | PR 생성 (약어는 괄호로 병기) |

명령어를 알려줄 때는 **한 번에 하나만**, 왜 필요한지 한 줄 설명을 붙인다.

## 절차

### 1. 지금 상태 확인

```
git status --porcelain
git branch --show-current
```

- **저장 안 된 변경이 있으면 먼저 멈춘다.** 무엇이 바뀌었는지 보여주고,
  지금 자리에서 저장할지 / 새 복사본으로 가져갈지 물어본다. 임의로 버리지 않는다.
- 이미 `main` 이 아닌 곳에 있으면, 하던 작업이 끝났는지 확인한다.
  안 끝났으면 새로 만들지 말고 하던 걸 계속하라고 안내한다.

### 2. main 을 최신으로

```
git checkout main
```
```
git pull --ff-only origin main
```

이걸 빠뜨리는 게 **초보자 사고 1위**다. 어제 누군가 합친 코드를 모른 채
옛날 코드 위에서 작업하면, 나중에 합칠 때 충돌이 난다.

`--ff-only` 는 "깔끔하게 이어붙일 수 있을 때만 받아라"는 뜻이다. 꼬인 상태를
조용히 만들지 않고, 문제가 있으면 그 자리에서 멈춘다.

### 3. 이름 정하기

무엇을 만들 것인지 물어보고, 아래에서 종류를 고른다.

| 종류 | 언제 |
|---|---|
| `feat/` | 새 기능 |
| `fix/` | 버그 수정 |
| `docs/` | 문서만 |
| `chore/` | 설정, 정리 |

**이름은 영어 소문자와 하이픈만.** 한글이나 띄어쓰기가 들어가면 다른 사람
컴퓨터에서 깨진다. 사용자가 한글로 말하면 영어로 바꿔서 제안하고,
**그 이름으로 괜찮은지 확인받은 뒤에** 만든다.

예: "댓글 폼 만들래" → `feat/comment-form`

### 4. 복사본 만들기

```
git checkout -b <정한-이름>
```

### 5. 어디에 있는지 알려주기

초보자에게 가장 헷갈리는 건 "지금 내가 어디 있는가"다. 만든 뒤 반드시 알려준다.

- 지금 어느 복사본 안에 있는지
- 여기서 무엇을 고쳐도 `main`(인터넷에 올라가 있는 진짜 코드)은 안전하다는 것
- 다 되면 저장 지점을 만들고 → GitHub에 올리고 → 규민에게 합쳐달라고 요청한다는 것

## 하지 않을 것

- **복사본만 만들고, 커밋까지 대신 하지 않는다.** 무엇을 고칠지는 사용자가 정한다.
- `main` 에서 저장이 차단됐다는 이유만으로 사용자 확인 없이 이름을 지어 만들지 않는다.
  무슨 작업인지 먼저 물어본다.
