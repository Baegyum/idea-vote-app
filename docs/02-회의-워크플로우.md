# 02. 아이디어 회의 & 팀 운영 워크플로우

> 도구: **카톡방**(즉시 소통) + **Notion**(아이디어/회의록) + **GitHub Issues**(할 일) + **GitHub PR**(코드)
> 원칙: **아이디어는 Notion, 할 일은 GitHub.** 이 둘을 섞지 않습니다.

---

## 1. 각 도구의 역할 (섞지 않기)

| 도구 | 여기에만 쓰는 것 | 여기에 쓰지 말 것 |
|---|---|---|
| **카톡방** | "지금 막혔어", "회의 30분 늦어" 같은 실시간 소통 | 결정 사항 (스크롤되어 사라집니다) |
| **Notion** | 아이디어 후보, 회의록, 결정 기록 | 코드 관련 할 일 |
| **GitHub Issues** | "이 화면 만들기" 같은 구체적 할 일 | 아직 정해지지 않은 아이디어 |
| **GitHub PR** | 코드 리뷰 | 잡담 |

**가장 중요한 규칙: 카톡에서 뭔가 결정됐으면, 반드시 Notion이나 Issue로 옮겨 적습니다.**
카톡은 3일 지나면 아무도 못 찾습니다.

---

## 2. Notion 구조 (10분이면 만듭니다)

Notion 무료 플랜으로 충분합니다. 워크스페이스 하나에 페이지 4개:

```
📁 우리팀 워크스페이스
├── 💡 아이디어 뱅크        (데이터베이스 — 표)
├── 📝 회의록               (데이터베이스 — 회의 1회당 1페이지)
├── 🎯 현재 프로젝트         (지금 뭘 만들고 있는지 한 페이지)
└── 📚 배운 것 모음          (막혔던 것 + 해결법 아카이브)
```

### 2-1. 💡 아이디어 뱅크 — 표 속성

| 속성 이름 | 종류 | 값 |
|---|---|---|
| 아이디어 | 제목 | 한 줄 요약 |
| 제안자 | 선택 | 규민 / 재환 / 위진 |
| 어떤 문제를 푸나 | 텍스트 | 필수. 이게 없으면 아이디어가 아닙니다 |
| 주 사용자 | 텍스트 | "누가 돈 내고 쓸까?" |
| 규민 점수 | 숫자 (1-5) | 회의 전에 각자 매김 |
| 재환 점수 | 숫자 (1-5) | |
| 위진 점수 | 숫자 (1-5) | |
| 합계 | 수식 | `prop("규민 점수") + prop("재환 점수") + prop("위진 점수")` |
| 상태 | 선택 | 🌱후보 / 🔍조사중 / ✅채택 / 💤보류 |
| 회의일 | 날짜 | 언제 논의했는지 |

> **팁:** "합계" 기준 내림차순 정렬 뷰를 하나 만들어두면 회의가 5분 단축됩니다.

### 2-2. 📝 회의록 템플릿 (Notion 템플릿 버튼으로 저장)

```markdown
# 2026-09-07 정기회의

## 참석 : 규민 / 재환 / 위진
## 지난 회의 액션 아이템 점검
- [ ] (지난주에 정한 것들)

## 오늘 논의한 아이디어
| 아이디어 | 좋은 점 | 걱정되는 점 | 결론 |
|---|---|---|---|
|  |  |  |  |

## 오늘의 결정 사항  ← ★ 여기가 제일 중요
1.
2.

## 다음까지 할 일 (→ GitHub Issue로 등록)
- [ ] 재환 :
- [ ] 위진 :
- [ ] 규민 :

## 다음 회의 : 2026-09-14 (일) 20:00
```

## 3. 주간 리듬 (권장)

```
 월~토   각자 짬날 때 Notion 아이디어 뱅크에 아이디어 던져놓기 (형식 자유)
         + 배정받은 GitHub Issue 작업 → PR 올리기

  토     회의 전날. 각자 아이디어 뱅크의 모든 항목에 1~5점 매기기
         → 점수를 미리 매겨두면 회의에서 "음... 글쎄..." 시간이 사라집니다

  일 20시  정기회의 (60분, 아래 3-1 참고)

 일 회의 후  규민이 결정사항을 GitHub Issue로 등록하고 담당자 배정
             → 카톡방에 "이슈 3개 올렸어, 확인해줘" 한마디
```

### 3-1. 회의 60분 진행표

| 시간 | 무엇을 | 진행 |
|---|---|---|
| 0-10분 | 지난주 회고 — 각자 "된 것 / 막힌 것" 1분씩 | 돌아가며 |
| 10-15분 | 지난 액션 아이템 점검 (Notion 체크박스) | 규민 |
| 15-40분 | 아이디어 뱅크 상위 3개만 깊게 논의 | 제안자가 설명 |
| 40-50분 | **결정.** 채택 / 보류 / 폐기 중 하나로 반드시 마무리 | 만장일치 아니면 점수 합계 우선 |
| 50-60분 | 다음 주 할 일 배분 + 난이도 표시 | 규민 |

> **결정을 미루지 마세요.** "다음에 더 생각해보자"가 두 번 나오면 그 아이디어는 폐기입니다.
> 초보 팀이 죽는 이유 1위는 실력 부족이 아니라 **아무것도 결정하지 않아서**입니다.

### 3-2. 아이디어 평가 기준 (1~5점을 매기는 근거)

점수를 매길 때 이 4가지를 봅니다:

1. **문제가 진짜인가?** — 내 주변에 이걸로 불편해하는 사람이 3명 이상 떠오르는가
2. **우리가 3개월 안에 만들 수 있나?** — 못 만들 앱은 아무리 좋아도 0점
3. **처음 100명을 어떻게 데려올지 말할 수 있나?** — 못 하면 만들어도 아무도 안 씁니다
4. **우리가 이걸 6개월 붙잡고 있을 만큼 재밌어하나?** — 진심으로 중요합니다

## 4. 회의 결정 → 코드까지 가는 전체 흐름

```
① 아이디어 (Notion 아이디어 뱅크)
        │  회의에서 채택
        ▼
② 기능 쪼개기 (Notion 회의록 "다음까지 할 일")
        │  규민이 옮겨 적음
        ▼
③ GitHub Issue 등록  ← 난이도(🟢🟡🔴)와 "힌트" 칸을 규민이 채움
        │  담당자 배정 (카톡방에 알림)
        ▼
④ 담당자가 브랜치 만들고 작업 (docs/01-git-기초.md 대로)
        │
        ▼
⑤ PR 생성 → CI 자동 검사(초록 체크)
        │
        ▼
⑥ 규민 리뷰 → 수정 요청 or 승인
        │
        ▼
⑦ 규민이 Merge → main 갱신 → 자동 배포
        │
        ▼
⑧ 다음 회의에서 "이번 주에 이거 됐다" 공유
```

**이 흐름을 8주만 돌리면 재환·위진은 더 이상 초보가 아닙니다.**

## 5. 이슈 난이도 배분 원칙 (규민용)

초보에게 어려운 이슈를 주면 그 주가 통째로 날아갑니다. 이렇게 나누세요:

- 🟢 **1~4주차 재환·위진에게 줄 것**: 글자 바꾸기, 색 바꾸기, 문서 수정, 버튼 하나 추가, 정렬 탭 추가
- 🟡 **5~8주차**: 새 컴포넌트 하나 만들기, API 하나 추가하기
- 🔴 **규민이 하거나 화면 공유하며 같이**: DB 스키마 변경, 인증, 배포 설정, 라이브러리 추가

> 첫 PR은 **README에 자기 이름 한 줄 추가하기** 정도로 잡으세요.
> 목표는 코드가 아니라 **"pull → branch → commit → push → PR → merge" 한 바퀴를 몸으로 겪는 것**입니다.

---

## 6. 구글 스프레드시트를 쓸 경우

Notion 대신 스프레드시트를 쓴다면 시트 3장으로 똑같이 만들 수 있습니다:

- `아이디어뱅크` — 위 2-1의 열을 그대로. 합계는 `=SUM(E2:G2)`, 정렬은 데이터 > 필터
- `회의록` — 날짜별로 행 추가 (긴 글은 셀 안에서 `Alt+Enter` 줄바꿈)
- `주간현황` — 이름 × 주차 표에 이슈 번호와 상태

> 기능은 Notion이 낫지만, **셋 다 이미 익숙한 도구가 스프레드시트라면 그게 정답입니다.**
> 도구 배우다가 지치는 것보다 익숙한 걸로 굴리는 게 훨씬 낫습니다.
