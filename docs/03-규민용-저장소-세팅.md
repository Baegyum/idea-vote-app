> 이걸 해두면 재환이 실수로도 `main` 을 망가뜨릴 수 없게 됩니다.

## 2. 팀원 초대

`Settings` > `Collaborators` > `Add people`
→ 재환 아이디 입력 → 권한은 **Write** (Admin 아님, Maintain 아님)

> Write = 브랜치 만들고 푸시하고 PR 올릴 수 있음. **머지는 못 함.** 우리가 원하는 딱 그것.

---

## 3. ★ 브랜치 보호 규칙 (가장 중요)

`Settings` > `Branches` > `Add branch protection rule`

- **Branch name pattern**: `main`
- ☑ **Require a pull request before merging**
  - ☑ Require approvals → **1**
  - ☑ Dismiss stale pull request approvals when new commits are pushed
  - ☑ **Require review from Code Owners** ← CODEOWNERS 파일 덕분에 규민이 자동 리뷰어가 됩니다
- ☑ **Require status checks to pass before merging**
  - `check` 선택 (CI가 한 번 돌아간 뒤에야 목록에 뜹니다)
- ☑ **Do not allow bypassing the above settings** ← 규민 본인에게도 적용. 실수 방지용으로 켜두길 권장
- ☐ Allow force pushes (**절대 체크하지 말 것**)
- ☐ Allow deletions (**절대 체크하지 말 것**)

이 설정이 켜지는 순간, 재환이 어떤 실수를 해도 `main` 은 안전합니다.
**이 안전망이 있어야 재환에게 "마음껏 해봐"라고 말할 수 있습니다.**

## 5. 머지 설정

`Settings` > `General` > `Pull Requests`

- ☑ Allow squash merging ← **이것만** 켜기
- ☐ Allow merge commits
- ☐ Allow rebase merging
- ☑ Automatically delete head branches ← 머지된 브랜치 자동 삭제. 목록이 깔끔해집니다

> **Squash merge**: PR 안의 커밋 10개를 `main` 에서는 1개로 합칩니다.
> 초보 팀에게 필수입니다. 재환이 "오타 수정", "다시 오타 수정" 같은 커밋을 20개 만들어도
> `main` 의 역사는 깨끗하게 유지됩니다. 그러니 재환에게 **커밋을 마음껏 하라고** 말해주세요.

---

## 6. Supabase 프로젝트 만들기

1. https://supabase.com 가입 → `New project` (리전은 **Northeast Asia (Seoul)**)
2. `SQL Editor` 에 [db/schema.sql](../db/schema.sql) 전체를 붙여넣고 `Run`
3. `Authentication` > `Providers` > Email 켜기, **Confirm email** 켜두기
4. `Authentication` > `URL Configuration` > Redirect URLs 에 추가:
   - `http://localhost:3000/auth/callback`
   - `https://배포주소/auth/callback`
5. `Settings` > `API` 에서 URL과 anon key 복사
   → **개인톡으로** 재환에게 전달 (단톡방 ❌)

> anon key는 브라우저에 노출되는 공개 키라 그 자체로는 위험하지 않습니다.
> 다만 RLS 정책이 방어선이므로, `db/schema.sql` 의 RLS 부분은 절대 지우지 마세요.
> `service_role` 키는 **누구에게도, 어디에도 공유하지 마세요.**

## 7. 배포 (Vercel)

1. https://vercel.com 을 GitHub 계정으로 로그인
2. `Add New` > `Project` > `idea-vote-app` import
3. Environment Variables 에 `.env.local` 의 세 값을 그대로 등록
4. Deploy

이후 `main` 에 머지될 때마다 자동 배포됩니다.
PR마다 **미리보기 주소**도 자동 생성되니, 리뷰할 때 코드 대신 화면으로 확인할 수 있습니다.
→ 재환에게 "네 PR 화면 여기서 볼 수 있어" 하고 링크를 주면 성취감이 확 올라갑니다.

## 8. 첫 주에 만들어둘 이슈 (연습용 🟢)

재환의 **첫 PR을 반드시 성공**시켜야 합니다. 난이도를 일부러 낮추세요.

| # | 제목 | 담당 | 내용 |
|---|---|---|---|
| 1 | [작업] README에 팀원 소개 추가 | 재환 | `README.md` 에 자기 이름 한 줄 |
| 2 | [작업] README에 팀원 소개 추가 | 규민 | 같은 파일 → **일부러 충돌(conflict)을 경험시키기** |
| 3 | [작업] 홈 화면 빈 상태 문구 바꾸기 | 재환 | `app/page.tsx` 의 "아직 아이디어가 없어요" 수정 |
| 4 | [작업] 강조 색상 바꿔보기 | 재환 | `app/globals.css` 의 `--accent` 값 변경 |

> 2번은 의도적인 설계입니다. 같은 파일 같은 줄을 동시에 고치게 해서
> **충돌(conflict)을 안전한 상황에서 한 번 겪게** 만드는 겁니다.
> 나중에 진짜 중요한 코드에서 처음 만나면 훨씬 무섭습니다.
