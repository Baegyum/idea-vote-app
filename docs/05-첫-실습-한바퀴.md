# 05. 첫 실습 — 한 바퀴 돌기

> **목표는 코드를 잘 짜는 게 아닙니다.**
> 초대 수락부터 PR 생성까지 **한 바퀴를 완주하는 것**이 전부입니다.
> 오늘 바꾸는 건 글자 몇 개뿐이지만, 그 글자가 인터넷에 올라가는 경로를 몸으로 겪게 됩니다.
>
> 소요 시간: 설치 포함 **약 1시간**. 설치가 끝나 있다면 20분.
> 막히면 **15분 규칙** — 혼자 15분 넘기지 말고 카톡방에 스크린샷.

---

## 준비물 확인

시작 전에 이게 다 되어 있어야 합니다. 안 되어 있으면 [00-처음-시작하기.md](00-처음-시작하기.md) 먼저.

- [ ] Git, Node.js, VS Code 설치 완료
- [ ] GitHub 가입 완료, 규민에게 아이디 전달함
- [ ] 규민이 보낸 **저장소 초대 메일**을 수락함
- [ ] 클로드 코드 설치 및 로그인 완료

---

## 1단계. 코드 내려받기 (clone)

터미널을 엽니다. **Git Bash를 권장합니다** — PowerShell은 `npm` 실행을 막는 경우가 있습니다.
(바탕화면이나 아무 폴더에서 **우클릭 → `Git Bash Here`**)

```bash
cd ~/Desktop
```
```bash
mkdir -p projects && cd projects
```
```bash
git clone https://github.com/Baegyum/idea-vote-app.git
```

로그인 창이 뜨면 `Sign in with your browser` → 브라우저에서 승인.

```bash
cd idea-vote-app
```

> **`Repository not found` 이 뜨면** 초대를 아직 수락하지 않은 것입니다. 메일함을 확인하세요.

---

## 2단계. 부품 설치와 열쇠 파일

```bash
npm install
```

> 2~5분 걸립니다. 글자가 폭포처럼 쏟아지는 게 정상입니다.
> `npm : 이 시스템에서 스크립트를 실행할 수 없으므로...` 가 뜨면 → [04-막혔을때.md](04-막혔을때.md) 첫 항목 참고 (`npm.cmd` 를 쓰거나 Git Bash로 옮기면 됩니다)

이제 **규민이 개인톡으로 보내준 두 줄**을 넣을 파일을 만듭니다:

```bash
cp .env.example .env.local
```

VS Code로 폴더를 열고 `.env.local` 파일을 클릭해서, 두 줄의 값을 규민이 준 것으로 채웁니다:

```
NEXT_PUBLIC_SUPABASE_URL=규민이 준 주소
NEXT_PUBLIC_SUPABASE_ANON_KEY=규민이 준 키
```

> ⚠️ 이 값은 **단톡방·GitHub·블로그 어디에도 올리면 안 됩니다.** 우리 데이터베이스 접속 정보입니다.
> `.env.local` 은 `.gitignore` 에 등록돼 있어 실수로 커밋해도 올라가지 않습니다. 그래도 조심하세요.

---

## 3단계. 내 컴퓨터에서 앱 띄우기

```bash
npm run dev
```

`Ready in ...` 이 뜨면 브라우저에서 **http://localhost:3000** 접속.

> **`Port 3000 is in use ... using 3001 instead`** 라고 나오면 → **http://localhost:3001** 로 들어가면 됩니다.
> 에러가 아닙니다. 3000번을 다른 프로그램이 쓰고 있을 뿐입니다.

**아이디어 보드 화면이 뜨면 성공입니다.** 🎉
지금 보고 있는 이 화면이 https://idea-vote-app.vercel.app 과 **같은 코드, 같은 데이터베이스**입니다.

로그인 버튼을 눌러 자기 이메일로 한 번 로그인해보세요. 메일로 온 링크를 클릭하면 됩니다.

> 서버를 끄려면 터미널에서 `Ctrl + C`.
> **다음 단계부터는 터미널 창이 하나 더 필요합니다.** 서버는 켜둔 채로, 새 Git Bash 창을 여세요.

---

## 4단계. ★ 작업 시작 전 의식 — 두 줄

**이걸 건너뛰는 게 초보자 사고 1위입니다.** 반드시 먼저 하세요.

```bash
git checkout main
```
```bash
git pull
```

> 다른 사람 코드가 이미 합쳐졌을 수 있습니다. 옛날 코드 위에서 작업하면 나중에 충돌이 납니다.

이제 **내 작업 사본(브랜치)** 을 만듭니다. 이름은 `docs/자기이름-소개` 로 하세요:

```bash
git checkout -b docs/jaehwan-intro
```

확인:

```bash
git status
```

`On branch docs/jaehwan-intro` 라고 나오면 준비 완료입니다.

---

## 5단계. 클로드 코드로 수정하기

같은 폴더에서:

```bash
claude
```

클로드가 뜨면 **한국어로** 이렇게 말하세요:

> README.md의 팀 소개 표 아래 주석 부분에, 내 소개를 한 줄 추가해줘.
> 나는 재환이고, "개발 처음이지만 열심히 해보겠습니다" 정도로 써줘.

클로드가 파일을 고칩니다. **무엇을 고쳤는지 화면에 보여주니 읽어보세요.**
마음에 안 들면 그냥 말로 고쳐달라고 하면 됩니다:

> 문구를 좀 더 짧게 바꿔줘

**직접 고쳐도 됩니다.** VS Code에서 `README.md` 를 열어 타이핑해도 결과는 같습니다.

### 고친 게 화면에 반영됐는지 확인

브라우저로 돌아가 새로고침해보세요. (README는 화면에 안 나오지만, 나중에 색이나 문구를 고칠 땐 여기서 확인합니다)

### 검사 돌리기

PR을 올리기 전에 반드시:

```bash
npm run typecheck
```
```bash
npm run lint
```

**아무 메시지도 안 나오면 통과입니다.** 뭔가 빨갛게 나오면 그 내용을 클로드에게 그대로 보여주세요.

---

## 6단계. 저장하고 GitHub에 올리기

지금 뭘 고쳤는지 확인:

```bash
git status
```

빨간 글씨로 `modified: README.md` 가 보이면 정상입니다.

```bash
git add .
```
```bash
git commit -m "docs: 재환 팀원 소개 추가"
```

> 커밋 메시지 형식은 [CLAUDE.md](../CLAUDE.md) 3번 참고.
> 종류는 `feat`(기능) / `fix`(버그) / `docs`(문서) / `chore`(설정) 중 하나.

```bash
git push -u origin docs/jaehwan-intro
```

> 브랜치 이름은 4단계에서 만든 것과 **똑같이** 적어야 합니다.
> 다음부터는 그냥 `git push` 만 치면 됩니다.

---

## 7단계. PR 만들기 — 마지막 관문

`push` 하면 터미널에 이런 주소가 나옵니다:

```
remote: Create a pull request for 'docs/jaehwan-intro' on GitHub by visiting:
remote:      https://github.com/Baegyum/idea-vote-app/pull/new/docs/jaehwan-intro
```

**`Ctrl` 을 누른 채 그 주소를 클릭**하면 브라우저가 열립니다.

양식이 자동으로 채워져 있습니다. 빈칸만 채우세요:

- **무엇을 했나요?** → `README에 제 소개를 한 줄 추가했습니다.`
- **어떻게 확인했나요?** → 체크박스 3개 클릭
- **규민에게 물어보고 싶은 것** → 막혔던 부분이나 이해 안 된 걸 솔직하게. **이게 리뷰의 핵심입니다.**

초록 버튼 **`Create pull request`** 클릭.

마지막으로 **카톡방에 PR 주소를 붙여넣고** 이렇게 남기세요:

> 규민아 첫 PR 올렸어! 리뷰 부탁~
> https://github.com/Baegyum/idea-vote-app/pull/1

## 그다음에 일어나는 일

1. **CI가 자동으로 돕니다.** 1~2분 뒤 PR 화면에 초록 체크 ✓ 또는 빨간 ✗ 가 뜹니다.
   - ✗ 가 떠도 큰일 아닙니다. `Details` 를 눌러 로그를 보고, 그 내용을 클로드에게 보여주세요.
2. **규민이 리뷰합니다.** 보통 고칠 점을 코멘트로 남깁니다.
   - ⚠️ **지적은 여러분에 대한 평가가 아닙니다.** 코드에 대한 이야기이고, 경력 10년 차도 매일 받습니다.
3. **고칠 게 있으면** — 같은 브랜치에서 6단계(`add` → `commit` → `push`)를 다시 하면 됩니다. PR은 자동으로 갱신됩니다. 새로 만들지 마세요.
4. **규민이 `Merge` 를 누르면 끝.** 여러분의 코드가 `main` 에 들어가고, 몇 분 뒤
   **https://idea-vote-app.vercel.app 에 자동으로 반영됩니다.**

## 오늘의 진짜 성과

README에 한 줄 추가한 게 아닙니다. 여러분은 방금:

```
받고 → 만들고 → 고치고 → 담고 → 저장하고 → 올리고 → 부탁한다
pull   branch   수정    add    commit    push     PR
```

**실무에서 쓰는 협업 흐름을 한 바퀴 완주했습니다.** 앞으로 하는 모든 작업이 이 일곱 단계의 반복입니다. 바뀌는 건 5단계(고치는 내용)뿐입니다.

다음 작업부터는 [01-git-기초.md](01-git-기초.md) 만 열어두고 진행하면 됩니다.

## 자주 막히는 곳 요약

| 증상 | 원인 | 해결 |
|---|---|---|
| `Repository not found` | 초대 미수락 | 메일함에서 초대 수락 |
| `npm : 스크립트를 실행할 수 없으므로` | PowerShell 보안 정책 | `npm.cmd` 를 쓰거나 Git Bash 사용 |
| `'npm'/'git' 인식되지 않습니다` | 설치 후 터미널이 PATH를 모름 | **터미널 창을 닫고 새로 열기** |
| `Port 3000 is in use` | 3000번 사용 중 | 3001 로 접속하면 됨 (에러 아님) |
| 화면은 뜨는데 로그인이 안 됨 | `.env.local` 값이 비었거나 틀림 | 규민이 준 값 다시 확인 |
| `fatal: not a git repository` | 프로젝트 폴더 밖 | `cd ~/Desktop/projects/idea-vote-app` |

더 자세한 건 [04-막혔을때.md](04-막혔을때.md).
