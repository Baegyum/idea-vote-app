# 01. Git 기초 — 매일 쓰는 7개 명령어

> 외우지 마세요. 작업할 때마다 이 문서를 열어놓고 복사해서 쓰면 됩니다.
> 세 달쯤 지나면 자연스럽게 외워집니다.

---

## 왜 이렇게 복잡한가?

세 명이 같은 파일을 동시에 고치면 **덮어쓰기 사고**가 납니다.
Git은 이걸 막기 위해 이런 구조를 씁니다:

```
       GitHub (인터넷의 원본)
              │  main 브랜치 ← 완성된 코드만
              │
   ┌──────────┼──────────┐
   ▼          ▼          ▼
 규민 PC    재환 PC    위진 PC
           feat/댓글   feat/정렬     ← 각자 자기 "복사본"에서 작업
```

각자 **브랜치(branch)** 라는 자기만의 복사본에서 작업하고,
다 되면 규민에게 "합쳐주세요" 하고 요청(PR)합니다.
규민이 확인하고 합쳐야만 `main` 에 들어갑니다. **그래서 사고가 안 납니다.**

---

## 매일 쓰는 7개

### ① 최신 코드 받아오기 — 작업 시작 전에 항상!

```bash
git checkout main
```
```bash
git pull
```

> **왜?** 어제 규민이 다른 사람 코드를 합쳤을 수 있습니다. 옛날 코드 위에서 작업하면 나중에 충돌이 납니다.
> **이 두 줄을 안 하고 작업하는 게 초보자 사고 1위입니다.**

### ② 새 브랜치 만들기 — 작업 하나당 브랜치 하나

```bash
git checkout -b feat/comment-form
```

> `feat/` = 새 기능, `fix/` = 버그 수정, `docs/` = 문서.
> 뒤의 이름은 영어 소문자와 하이픈으로. 무슨 작업인지 알아볼 수 있게.

### ③ 지금 상태 확인 — 헷갈릴 때마다

```bash
git status
```

> 지금 어느 브랜치인지, 어떤 파일을 고쳤는지 알려줍니다. **하루에 열 번 쳐도 됩니다. 아무것도 안 망가집니다.**

### ④ 고친 파일 담기

```bash
git add .
```

> `.` 은 "고친 것 전부". 장바구니에 담는다고 생각하세요.

### ⑤ 저장 지점 만들기 (커밋)

```bash
git commit -m "feat: 아이디어 상세 화면에 댓글 폼 추가"
```

> 장바구니를 계산해서 **되돌릴 수 있는 저장 지점**을 만드는 것.
> 메시지 형식은 [CLAUDE.md](../CLAUDE.md) 3번 참고.
> 작업이 크면 중간중간 여러 번 커밋하세요. 잘게 쪼갤수록 리뷰가 쉽습니다.

### ⑥ GitHub에 올리기

```bash
git push -u origin feat/comment-form
```

> 브랜치 이름은 ②에서 만든 것과 똑같이. `-u origin ...` 은 처음 한 번만,
> 그다음부터는 그냥 `git push` 만 치면 됩니다.

### ⑦ PR 만들기

`push` 하면 터미널에 이런 주소가 나옵니다:

```
remote: Create a pull request for 'feat/comment-form' on GitHub by visiting:
remote:      https://github.com/.../pull/new/feat/comment-form
```

**이 주소를 Ctrl 누른 채 클릭**하면 브라우저가 열립니다.
→ 양식이 자동으로 채워져 있으니 빈칸만 채우고 → 초록 버튼 `Create pull request`
→ **카톡방에 PR 주소를 붙여넣고 "규민아 리뷰 부탁~"**

---

## 그다음엔?

1. 규민이 리뷰합니다. 보통 **고칠 점을 코멘트로 남깁니다.**
   - ⚠️ 지적은 여러분 실력에 대한 평가가 아닙니다. 코드에 대한 이야기입니다. 경력 10년 차도 매일 받습니다.
2. 고쳐야 하면 **같은 브랜치에서** ④⑤⑥을 다시 하면 됩니다. PR은 자동으로 갱신됩니다.
3. 규민이 `Merge` 를 누르면 끝. 여러분의 코드가 `main` 에 들어갔습니다.
4. 다음 작업 전에 다시 ①번부터.

## 클로드 코드와 함께 쓰기

위 7단계를 클로드에게 시켜도 됩니다. 이렇게 말하세요:

> "이슈 12번 작업 시작할게. main 최신으로 받고 브랜치 만들어줘"
> "지금까지 고친 거 커밋해줘. 메시지는 규칙대로 지어줘"
> "푸시하고 PR 주소 알려줘"

단, **클로드는 머지를 하지 않습니다.** 그건 규민만 합니다. (CLAUDE.md에 그렇게 못 박아뒀습니다.)

---

## 절대 하면 안 되는 것 ⛔

| 명령어 | 왜 위험한가 |
|---|---|
| `git push --force` | 남의 작업을 지워버릴 수 있음 |
| `git reset --hard` | 내가 고친 걸 되돌릴 수 없게 날림 |
| `main` 에서 직접 작업 | 애초에 GitHub 설정으로 막아뒀지만, 시도도 하지 마세요 |

이 셋 중 하나를 쳐야 할 것 같으면 **먼저 카톡방에 물어보세요.**

