# 04. 막혔을 때 — 상황별 처방전

> 여기 있는 어떤 상황도 "망한 것"이 아닙니다. Git은 웬만해선 되돌릴 수 있습니다.

---

## 규칙: 15분 규칙

혼자 **15분** 해보고 안 되면 카톡방에 올립니다. 올릴 때는 이 3줄:

```
1. 뭘 하려고 했는지 :
2. 친 명령어 :
3. 나온 에러 (스크린샷 전체) :
```

에러 메시지를 **일부만** 캡처하지 마세요. 중요한 정보는 보통 아래쪽에 있습니다.

---

## 상황별 처방

### 😱 "실수로 main에서 작업해버렸어요"

아직 커밋 안 했다면 — 고친 내용을 그대로 새 브랜치로 옮길 수 있습니다:

```bash
git checkout -b feat/내작업이름
```

끝입니다. 고친 파일들이 새 브랜치로 따라옵니다. 아무것도 잃지 않았습니다.

### 😱 "커밋 메시지를 잘못 썼어요"

아직 push 안 했다면:

```bash
git commit --amend -m "feat: 올바른 메시지"
```

이미 push 했다면 → **그냥 두세요.** squash merge라 `main` 에는 안 남습니다.

### 😱 "conflict(충돌)가 났어요"

같은 줄을 두 사람이 다르게 고쳤을 때 납니다. **정상적인 일입니다.**

VS Code로 그 파일을 열면 이렇게 보입니다:

```
<<<<<<< HEAD
내가 쓴 내용
=======
상대방이 쓴 내용
>>>>>>> main
```

VS Code가 위에 **`Accept Current Change` / `Accept Incoming Change` / `Accept Both Changes`**
버튼을 띄워줍니다. 어느 쪽이 맞는지 판단이 안 되면 **카톡방에 물어보세요.**
정한 뒤 `<<<<<<<` `=======` `>>>>>>>` 기호가 남아있지 않은지 확인하고:

```bash
git add .
```
```bash
git commit -m "fix: 충돌 해결"
```
```bash
git push
```

### 😱 "고친 걸 전부 없던 걸로 하고 싶어요"

⚠️ **되돌릴 수 없습니다.** 정말 확실할 때만:

```bash
git checkout -- .
```

확신이 없으면 카톡방에 먼저 물어보세요.

### 😱 "push했는데 rejected 라고 나와요"

GitHub 쪽에 내가 모르는 새 커밋이 있다는 뜻입니다:

```bash
git pull --rebase
```
```bash
git push
```

### 😱 "'○○' 용어가 cmdlet, 함수, 스크립트 파일... 인식되지 않습니다"

방금 설치한 프로그램(`git`, `node`, `npm`, `gh` 등)에서 이 에러가 난다면,
**설치가 실패한 게 아닙니다.** 열려 있는 터미널 창이 아직 모르는 것뿐입니다.

컴퓨터는 "프로그램을 어디서 찾을지" 목록(PATH)을 갖고 있는데,
**터미널은 창이 열린 순간의 목록을 계속 씁니다.** 그래서 창을 연 뒤에 설치한 프로그램은 안 보입니다.

**해결: 터미널 창을 완전히 닫고 새로 여세요.** 그러면 갱신된 목록을 읽습니다.

> 그래도 안 되면 그때는 컴퓨터를 재부팅하세요.
> 재부팅까지 했는데도 안 되면 설치가 정말 안 된 것이니 카톡방에 알려주세요.

---

### 😱 "npm : 이 시스템에서 스크립트를 실행할 수 없으므로..."

윈도우에서 **가장 흔한 첫 관문**입니다. npm이 고장 난 게 아니라, PowerShell이 보안상 스크립트 파일 실행을 기본으로 막고 있는 것뿐입니다.

**방법 A — 설정을 안 건드리는 방법 (권장)**

`npm` 대신 `npm.cmd` 를 치세요. 이것만 바꾸면 그대로 동작합니다:

```bash
npm.cmd install
```
```bash
npm.cmd run dev
```

**방법 B — 아예 터미널을 바꾸기 (더 편함)**

PowerShell 대신 **Git Bash**를 쓰면 이 문제가 없습니다.
프로젝트 폴더를 탐색기에서 열고 → 빈 곳에 **우클릭 → `Git Bash Here`**
→ 열린 창에서는 `npm install` 이 그냥 됩니다.

**방법 C — PowerShell 정책 자체를 바꾸기**

⚠️ 이건 **컴퓨터의 보안 설정을 바꾸는 일**입니다. 위 A·B로 해결되면 하지 마세요.
꼭 필요하다면 무엇을 바꾸는지 이해한 뒤 본인이 직접 실행하세요:

```bash
Set-ExecutionPolicy -Scope CurrentUser -ExecutionPolicy RemoteSigned
```

> `RemoteSigned` = "내 컴퓨터에서 만든 스크립트는 실행 허용, 인터넷에서 받은 건 서명된 것만 허용".
> `-Scope CurrentUser` 라서 내 계정에만 적용되고 관리자 권한이 필요 없습니다.
> 그래도 **보안 설정 변경이므로, 규민에게 먼저 물어보고 하세요.**

---

### 😱 "npm run dev 했는데 에러가 잔뜩 나요"

십중팔구 부품이 안 맞는 겁니다. 순서대로:

```bash
git pull
```
```bash
npm install
```
```bash
npm run dev
```

그래도 안 되면 `node_modules` 폴더를 통째로 지우고 다시:

```bash
rmdir /s /q node_modules
```
```bash
npm install
```

### 😱 "내 브랜치가 뭐였는지 모르겠어요"

```bash
git branch
```

`*` 표시가 붙은 게 지금 브랜치입니다. (목록에서 빠져나오려면 `q`)

## 클로드에게 물어보는 요령

에러가 나면 **에러 전문을 통째로 복사해서** 클로드에게 붙여넣고 이렇게 말하세요:

> "이 에러 났어. 무슨 뜻이고 뭘 하면 돼? 나 완전 초보니까 명령어 하나씩만 알려줘."

클로드는 이 저장소의 [CLAUDE.md](../CLAUDE.md)를 읽고 있어서
우리 팀 규칙(main 직접 수정 금지 등)에 맞게 답합니다.

**단, 클로드가 `--force`나 `reset --hard`를 제안하면 실행하지 말고 카톡방에 먼저 물어보세요.**
